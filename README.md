# Поиск по чатам Telegram из Codex

`tg-mcp` — локальный MCP-сервер для поиска по ключевым словам и автору в группах и каналах любой тематики. Список чатов задаётся в `config.toml`. Поиск выполняется в Telegram и возвращает текст, дату, идентификатор автора и ссылку на сообщение, если Telegram поддерживает ссылку для этого чата.

## Подготовка на Windows

Понадобятся Python 3.11 или новее, аккаунт Telegram и `api_id` с `api_hash` из [Telegram API development tools](https://my.telegram.org/apps). Выполняйте команды в PowerShell из папки проекта.

Для Windows x64 с Python 3.12 есть установка с закреплёнными версиями и SHA-256 дистрибутивов:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-win-py312.lock
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation .
```

Один из дистрибутивов в списке, `pyaes`, собирается из исходников. Pip может отдельно установить инструменты для его сборки. [Изоляция сборки в pip](https://pip.pypa.io/en/stable/reference/build-system/#build-isolation)

Для другой версии Python используйте обычную установку:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
```

При обновлении окружения со старым пакетом `relocation-telegram-mcp` сначала остановите сервер и выполните `.\.venv\Scripts\python.exe -m pip uninstall relocation-telegram-mcp`. Затем установите `tg-mcp` по одному из вариантов выше. Это заменит пакеты в окружении с сохранением путей к командам MCP.

При первой настройке скопируйте `config.example.toml` в `config.toml` и заполните `api_id` и `api_hash` в секции `[telegram]`. Путь `session` задаётся относительно папки этого файла. Войдите в Telegram через отдельный терминал, где можно ввести код и пароль двухэтапной аутентификации:

```powershell
.\.venv\Scripts\tg-mcp-setup.exe --config config.toml login
.\.venv\Scripts\tg-mcp-setup.exe --config config.toml chats --toml
```

Команда `chats` заполняет кеш идентификаторов сессии. С флагом `--toml` она выводит готовую секцию `[chats]` с названиями в комментариях и сохраняет заданные псевдонимы. Оставьте строки нужных чатов и замените секцию в `config.toml`. Чтобы добавить только новые чаты, вставьте их строки под существующим заголовком `[chats]`.

```toml
[chats]
community = -1001234567890
housing = -1009876543210
```

`config.toml` и файл `.session` содержат данные доступа. Оба исключены из Git при использовании имён из примера. Команды настройки и MCP используют одну сессию и блокируют её на время работы. Если сессия занята, остановите использующий её процесс и повторите команду.

## Запуск и подключение к Codex

Один процесс `tg-mcp` держит Telegram-сессию и принимает запросы от нескольких чатов Codex одновременно по Streamable HTTP. Все клиенты используют один список разрешённых Telegram-чатов.

1. Сгенерируйте токен командой `.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"`. Запишите его в `token` в секции `[http]` файла проекта `config.toml`.

   ```toml
   [http]
   port = 8765
   token = "вставьте-сгенерированный-токен"
   ```

2. Запустите сервер из папки проекта и оставьте его работать. Он слушает только `127.0.0.1` и требует токен в каждом запросе.

   ```powershell
   .\.venv\Scripts\tg-mcp.exe --config config.toml
   ```

3. При настройке подключения задайте секцию `[mcp_servers.telegram]` в конфигурации Codex и запустите Codex. Используйте тот же токен и порт, что в файле проекта. [Настройки MCP в Codex](https://learn.chatgpt.com/docs/config-file/config-reference#mcp-servers)

   ```toml
   [mcp_servers.telegram]
   url = "http://127.0.0.1:8765/mcp"
   http_headers = { Authorization = "Bearer вставьте-сгенерированный-токен" }
   startup_timeout_sec = 25
   ```

Чтобы подхватить новый список Telegram-чатов, перезапустите процесс сервера. Перед запуском `tg-mcp-setup` остановите его через Ctrl+C, чтобы освободить сессию.

## Поиск

- `list_search_chats()` возвращает только имена из `[chats]`.
- `search_messages(chat, query?, author?, since?, until?, limit?, offset_id?)` ищет в одном чате. Укажите `query`, `author` или оба параметра. `author` принимает числовой Telegram ID пользователя или точный `@username`. `since` включается в диапазон, `until` исключается. Используйте дату и время с часовым поясом. Размер страницы от 1 до 50.
- `get_message_context(chat, message_id, before=5, after=5)` возвращает реплику, контекст до и после неё и сообщение, на которое ответили внутри того же чата, даже если оно лежит вне окна. Возьмите имя чата и ID из результата поиска. Окно запрашивает от 0 до 20 записей истории с каждой стороны. Результат может быть короче, если в окне есть служебные или недоступные сообщения. В форумах окно показывает общую хронологию чата.
- Для поиска по нескольким чатам Codex вызывает инструмент для каждого выбранного имени. Для следующей страницы передайте `next_offset_id` как `offset_id` и сохраните остальные ограничения. Продолжайте до `next_offset_id: null`, даже если промежуточная страница пуста. История идёт от новых сообщений к старым, при выводе хронологии её можно отсортировать по датам.

Примеры запросов к Codex:

> В чатах `community` и `housing` найди сообщения про депозит за последние три месяца. Укажи дату, чат и ссылку для каждого случая.

> Собери хронологию сообщений пользователя `@example` в чате `community` с 1 января по 1 апреля по московскому времени. Пройди все страницы за этот период. Укажи ссылки на сообщения и даты, которые покрывает поиск.

Для длинных историй используйте числовой `sender_id` из результатов. Он сохраняется при смене `@username`. По числовому ID Telethon обычно может найти только пользователя, с которым эта сессия уже встречалась. Если ID недоступен, попробуйте текущий `@username`. Поиск покрывает историю, доступную вашей сессии в выбранных чатах. [Как Telethon разрешает ID](https://docs.telethon.dev/en/stable/concepts/entities.html#entities-vs-input-entities)

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют подставные ответы Telegram и проверяют границу разрешённых чатов, поиск с продолжением выдачи и чтение контекста.
